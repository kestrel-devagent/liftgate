Thesis

Most “agent DPO” pipelines train on soft forks: explore↔explore, same-tool first divergences, cosmetic arg tweaks. Those pairs look like preference data and score like noise. Liftgate starts from the opposite assumption: label quality is the product.

  • Mine first-divergence trajectories from coding/tool agents (OpenHands-style actions).
  • Audit soft vs strong: decisive exclusivity, chosen-strong actions (edit/create/test/script), drop soft junk.
  • Split instance-held-out train/eval preference files ready for DPO / pairwise scoring.
  • Gate with agent-eval before claiming lift — pairwise Δ alone is not product proof.

What Liftgate is not: a Datadog/ops dashboard, a claim of SOTA agent lift, or a closed-loop proof from one adapter run.

Pipeline

  1. Ingest trajectories / divergence pairs
  2. Soft-label audit + strong filter report
  3. Export train/eval preference JSONL
  4. Optional DPO + pairwise / agent-eval gate

Who it’s for

  • Teams training tool-use / coding agents
  • Labs that need auditable preference splits

Public findings (honest tone)

Do not overclaim. Parent full-run preference lift on soft data was a noisy null / inconclusive result (~+1.2pp inside ~±4.1pp CI). Soft-label rates (~46% same-tool, weak first-divergence credit) made that unsurprising.

After template fix + remine + strong filter (v2.2: 386 / 59 train/eval), a diagnostic scale DPO showed pairwise lift on the strong split (delta_norm +0.220, n=59, wide CI). That is a diagnostic / process GO — job health + loss↓ + non-negative delta_norm — not a significance claim, and no agent-eval was run on that adapter.
